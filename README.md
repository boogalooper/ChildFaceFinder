# Child Face Finder

Windows-утилита для поиска детей на больших наборах фотографий по одному или нескольким эталонным изображениям каждого ребёнка.

## Главное в этой версии

- InsightFace `antelopev2` + ONNX Runtime GPU.
- Полный проход SCRFD по кадру плюс опциональный tiled-поиск маленьких лиц.
- Перекрывающиеся тайлы объединяются через NMS, поэтому одно лицо не должно дублироваться.
- Ведущий числовой индекс или отдельная заглавная латинская буква `A–Z` перед именем эталона не входят в ID ребёнка; обычная латиница в имени/фамилии сохраняется.
- Любое количество эталонов одного ребёнка хранится как отдельные embeddings; усреднения нет.
- Фильтрация качества для каждого лица отдельно: глаза, резкость, поворот, размер, экспозиция.
- Каждый критерий качества можно включить/выключить в GUI. Включённый критерий исключает пару ребёнок–фото из основного CSV и записывает её в `*_rejected.csv`.
- RAW обрабатывается быстрым путём: сначала используется встроенный JPEG-preview камеры, при необходимости — `rawpy` half-size fallback; промежуточный JPEG для RAW на диск не пишется. HEIC/HEIF/AVIF и редкие форматы при необходимости используют только системный `%TEMP%`, а временные файлы удаляются сразу.
- В корне проекта находятся только `run.bat`, `install.bat` и `README.md`. Остальные файлы лежат в обычных видимых папках `app` и `setup`; после установки также создаются обычные видимые `tools`, `venv`, `models`. Скрытые/системные каталоги не используются.
- После обычной установки можно опционально собрать автономную portable-папку; на целевой машине не нужен установленный Python/CUDA Toolkit, но для GPU остаётся нужен совместимый NVIDIA-драйвер.

## Имена эталонов

Папка эталонов **всегда сканируется рекурсивно**. Название подкаталога не входит в ID ребёнка. Поэтому можно хранить, например:

```text
Эталоны/
├─ портрет/
│  ├─ Котов Никита.jpg
│  ├─ Балаева Виктория.jpg
│  └─ Синичкина.jpg
└─ стоя/
   ├─ Котов Никита.jpg
   ├─ Балаева Виктория.jpg
   └─ Синичкина.jpg
```

Получатся три ребёнка с двумя эталонами каждый: `Котов Никита`, `Балаева Виктория`, `Синичкина`. Можно добавлять третью, четвёртую и последующие подпапки/эталоны с тем же ID — жёсткого лимита количества эталонов нет.

Поддерживается и прежняя схема с номером исходного кадра в начале имени:

```text
712 Котов Никита.jpg
709 Котов Никита.jpg
```

Ведущий числовой блок удаляется, поэтому оба файла относятся к `Котов Никита`.

Также допускаются отдельные ведущие индексы из **одной заглавной латинской буквы `A–Z`**:

```text
A Котов Никита.jpg
B Котов Никита.jpg
A Smith John.jpg
B Smith John.jpg
```

В этих примерах `A`/`B` считаются служебными индексами и удаляются. При этом латиница в самом идентификаторе полностью сохраняется: `Smith John.jpg`, `McDonald Anna.jpg`, `LEE John.jpg` остаются без изменений. Строчные буквы и многобуквенные латинские слова автоматически не удаляются.

Имя может состоять из фамилии и имени, только фамилии или другой устойчивой текстовой части — на кириллице, латинице или в смешанном написании. Сначала программа объединяет все точные нормализованные имена, независимо от количества файлов. Если несколько эталонов названы немного по-разному, допускается однозначная общая часть, например:

```text
Котов.jpg                 + Котов Никита.jpg
Котов Никита портрет.jpg  + Котов Никита стоя.jpg + Котов Никита улица.jpg
```

Во втором примере все три файла получат ID `Котов Никита`. В первом — `Котов`.

Чтобы не объединить разных детей случайно, короткое совпадение из одного слова разрешается только тогда, когда одно из имён целиком состоит из этого слова. Если одна общая часть подходит сразу к нескольким файлам (например, `Котов.jpg`, `Котов Никита.jpg`, `Котов Сергей.jpg`), программа **не угадывает**, а останавливается с понятным сообщением о неоднозначных именах.

Для внутренней группировки нормализуются регистр, лишние пробелы и `е/ё`; латинские символы не удаляются. Жёсткого ограничения количества эталонов на один ID нет. Практически можно использовать столько заведомо правильно отобранных фотографий ребёнка, сколько требуется.

### Как используются несколько эталонов

Embeddings **не усредняются**. Каждый эталон хранится отдельно. Для найденного лица вычисляется distance до каждого эталона каждого ребёнка, а итоговая distance ребёнка равна **лучшему (минимальному) значению среди всех его эталонов**. Поэтому дополнительный удачный эталон может улучшить распознавание другого ракурса, выражения лица или более старой/новой фотографии.

Второй кандидат при проверке неоднозначности — обязательно **другой ребёнок**, а не ещё один эталон того же ребёнка. Поэтому несколько эталонов одного ID не конкурируют друг с другом при расчёте «отрыва от второго ребёнка».

Если у ребёнка несколько эталонов, программа проверяет их взаимную согласованность. Для всех пар вычисляется cosine distance и в журнале контролируется худшая (максимальная) взаимная distance. Если она превышает порог предупреждения, программа указывает наиболее слабо совпадающую пару файлов, но не удаляет эталоны автоматически. Это помогает заметить случайно неверно подписанный файл.

Чем больше эталонов, тем больше сравнений выполняется на этапе matching, но эта операция очень лёгкая по сравнению с детекцией и анализом лиц. Для обычных наборов из нескольких эталонов на ребёнка влияние на скорость практически несущественно.

## Поиск маленьких лиц

В GUI есть три режима:

- `Быстрый` — один проход по полному кадру.
- `Улучшенный` — полный кадр + перекрывающиеся тайлы на больших изображениях. Рекомендуемый режим.
- `Максимальный` — более мелкие тайлы и больше проходов. Лучше для очень маленьких лиц, но медленнее.

SCRFD сохраняет штатный вход `640x640` на каждом проходе. Для большого группового фото тайлы позволяют не уменьшать весь кадр до 640 пикселей целиком.

После полного кадра и тайлов bbox объединяются NMS. Дубликаты одного лица удаляются до matching.

Параметр `Порог детектора` по умолчанию `0.18`. Это чувствительность первоначального поиска SCRFD, а не критерий качества кадра. Низкий `det_score` сам по себе не выбрасывает уже найденного ребёнка из result.csv.

## Фильтр качества

Пресет `Мягкий / Нормальный / Строгий` задаёт числовые пороги. Отдельные галочки задают, какие причины действительно должны отбраковывать фото:

- закрытые/сильно прищуренные глаза;
- нерезкое лицо;
- сильный yaw/pitch/roll;
- слишком маленькое лицо;
- плохая экспозиция.

Для групповой фотографии качество считается отдельно для каждого ребёнка. Если один ребёнок моргнул, он может попасть в `rejected.csv`, а остальные дети с того же кадра — в основной CSV.

Проверка глаз основана на 106 landmarks InsightFace и является эвристикой. Для спорных кадров полезно просматривать `*_rejected.csv`.

## CSV

Основной файл:

```text
Идентификатор ребенка;номер фото с этим ребенком
Котов Никита;IMG_0123
Балаева Виктория;IMG_0123
```

`номер фото` — имя исходного файла без расширения.

Дополнительно:

- `*_rejected.csv` — ребёнок распознан, но фото исключено включённым фильтром качества;
- `*_review.csv` — совпадение близко к порогу или слишком близок второй ребёнок.

## Форматы изображений

Обычные форматы читаются через Pillow/OpenCV: JPEG, PNG, TIFF, BMP, WebP и другие поддерживаемые форматы.

HEIC/HEIF/AVIF читаются через `pillow-heif`/Pillow.

RAW читается через `rawpy` / LibRaw: CR2, CR3, NEF, ARW, DNG, RAF, RW2, ORF и многие другие. Поддержка конкретного нового/редкого RAW зависит от LibRaw.

### TEMP

Для RAW сначала извлекается встроенный JPEG-preview без полной проявки сенсорных данных. Если preview отсутствует или слишком мал, используется быстрый `half_size=True` fallback LibRaw. Рабочая копия ограничивается 4096 px по длинной стороне. HEIF и редкие неизвестные форматы при необходимости нормализуются через системный `%TEMP%`.

- рядом со скриптом временные изображения не создаются;
- временный JPEG удаляется сразу после чтения обратно в память;
- общий каталог создаётся через `tempfile.TemporaryDirectory` и удаляется при успехе, ошибке или штатной отмене;
- временные ZIP установщика и модели также находятся в системном TEMP и удаляются.

## GPU и параллельная обработка

Основная конфигурация — NVIDIA GPU через `onnxruntime-gpu 1.26.0`/CUDA Execution Provider.

Конвейер разделён:

- несколько CPU-потоков декодируют обычные изображения и RAW;
- отдельные inference-потоки используют общие ONNX/InsightFace модели на GPU;
- очередь ограничена; RAW не проявляется без необходимости в полном разрешении, поэтому расход CPU/RAM существенно ниже.
- `.xmp` и другие служебные файлы пропускаются и не передаются декодеру.

Для RTX 5090 рекомендуется начать с `2` GPU inference-потоков. Если GPU заметно недогружен, можно попробовать `3–4`.

## Установка

Текущий установщик рассчитан на 64-битную Windows.

Системный Python не используется и не изменяется.

1. Запустите `install.bat`.
2. В видимую папку `tools` будет установлен зафиксированный `uv 0.12.5`.
3. `uv` установит собственный CPython `3.11.16` в `tools/python`.
4. Будет создана видимая папка `venv`.
5. Установятся зафиксированные зависимости и `insightface==1.0.1`.
6. Проверятся Tkinter и CUDA Execution Provider.
7. `antelopev2` будет установлен в `models/insightface/models/antelopev2`.
8. Выполнится GPU/model smoke-test.
9. После успешной установки установщик спросит, нужно ли сразу собрать portable-версию. Ответ `N`/Enter ничего дополнительного не создаёт.

После успешной установки запускайте `run.bat`. Для диагностики с консолью можно запустить `setup\run_console.bat`.

## Portable-сборка

Portable создаётся **опционально после обычной успешной установки**. Её можно собрать сразу, ответив `Y` на вопрос в конце `install.bat`, либо позже запустить `setup\build_portable.bat`.

Сборщик использует уже установленную и проверенную конфигурацию и создаёт:

```text
portable/
└─ ChildFaceFinder_Portable/
   ├─ run.bat
   ├─ run_console.bat
   ├─ README_PORTABLE.md
   ├─ app/
   ├─ models/
   └─ python/
      └─ Lib/site-packages/
```

Portable не является копией `venv`: виртуальные окружения Windows содержат привязку к исходному Python и не предназначены для простого переноса. Сборщик копирует управляемый CPython, а проверенные зависимости помещает непосредственно в штатный `python\Lib\site-packages` portable-Python. Поэтому portable запускается обычной командой `python\python.exe app\app.py`, без привязки к исходному пути `venv`, без `runpy` и без дополнительного bootstrap-кода.

На целевом Windows x64 компьютере для portable **не требуется** устанавливать Python, `uv`, `venv`, CUDA Toolkit или cuDNN. CUDA/cuDNN user-mode библиотеки из Python-пакетов входят в portable. Для GPU-режима всё равно нужны совместимая NVIDIA-видеокарта и достаточно свежий NVIDIA-драйвер — драйвер в portable не включается.

Перед завершением сборки portable-копия проходит те же проверки Python/Tkinter/CUDA и smoke-test InsightFace + `antelopev2`. Если portable-проверка не прошла, обычная установленная версия не изменяется.

Portable создаётся в обычной видимой папке `portable`; никаких Hidden/System атрибутов сборщик не назначает. Папку `ChildFaceFinder_Portable` нужно переносить целиком на другой компьютер. Нельзя переносить только `run.bat` отдельно от `app`, `python` и `models`.

## Рекомендуемые настройки первого запуска

- Поиск маленьких лиц: `Улучшенный`.
- Порог детектора: `0.18`.
- Фильтр качества: `Нормальный`.
- Порог совпадения: `0.45`.
- Отрыв от второго ребёнка: `0.04`.
- GPU inference-потоки: `2`.
- Отбраковывать глаза: включено.
- Отбраковывать нерезкость: включено.
- Отбраковывать поворот: включено.
- Отбраковывать маленькие лица: включено.
- Отбраковывать экспозицию: выключено на первом запуске.

Все основные настройки снабжены всплывающими подсказками `(?)` или подсказкой при наведении на сам элемент.

## Лицензия моделей InsightFace

У кода InsightFace и у предоставляемых проектом предобученных моделей разные условия. Перед использованием `antelopev2` в коммерческой работе необходимо проверить актуальные условия лицензирования InsightFace/model zoo.


### GPU runtime

Установщик фиксирует `onnxruntime-gpu 1.26.0` и `nvidia-cudnn-cu12 9.7.1.26`. Версия cuDNN намеренно не оставлена плавающей: более новые cuDNN могут менять набор динамических подбиблиотек.

## Очистка временных файлов

Рабочие временные файлы создаются только в системном TEMP. В нормальном режиме отдельные временные файлы удаляются сразу после использования, а рабочий TEMP-каталог удаляется при завершении обработки, ошибке или штатной отмене.

Для защиты от остатков после аварийного завершения рабочие каталоги имеют имя `ChildFaceFinder_run_<PID>_*`. При следующем запуске GUI и повторно перед обработкой программа проверяет TEMP и удаляет каталоги предыдущих экземпляров, процесс которых уже не существует. Активный каталог другого одновременно работающего экземпляра не удаляется. Каталоги старых версий без PID удаляются только после защитного периода, чтобы не затронуть параллельно работающую старую версию.
