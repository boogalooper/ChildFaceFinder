# Child Face Finder

Windows-утилита для поиска людей (детей и взрослых) на больших наборах фотографий по одному или нескольким эталонным изображениям каждой цели.

Интерфейс согласован с Photo Select AI: в обоих приложениях используются одинаковые названия основных действий — «НАЧАТЬ АНАЛИЗ», «Поиск маленьких лиц», «Критерии качества», «Параллельные GPU-сеансы», «Журнал» и «Отмена». Специализированная терминология сохранена: здесь «цель» означает человека, заданного эталонами, а «серия» строится отдельно для уже распознанной цели.

## Главное в этой версии

- InsightFace `antelopev2` + ONNX Runtime GPU.
- Полный проход SCRFD по кадру плюс опциональный tiled-поиск маленьких лиц.
- Перекрывающиеся тайлы объединяются через NMS, поэтому одно лицо не должно дублироваться.
- Ведущий числовой индекс или отдельная заглавная латинская буква `A–Z` перед именем эталона не входят в ID ребёнка; обычная латиница в имени/фамилии сохраняется.
- Любое количество эталонов одного ребёнка хранится как отдельные embeddings; усреднения нет.
- Фильтрация качества для каждого лица отдельно: глаза, резкость, поворот, размер, экспозиция.
- Каждый критерий качества можно включить/выключить в GUI. Включённый критерий исключает пару ребёнок–фото из основного CSV и записывает её в `*_rejected.csv`.
- RAW обрабатывается быстрым путём: сначала используется встроенный JPEG-preview камеры, при необходимости — `rawpy` half-size fallback; промежуточный JPEG для RAW на диск не пишется. HEIC/HEIF/AVIF и редкие форматы при необходимости используют только системный `%TEMP%`, а временные файлы удаляются сразу.
- В корне проекта находятся только `run.bat`, `install.bat` и `README.md`. Остальные файлы лежат в обычных видимых папках `app` и `setup`; после установки также создаются обычные видимые `tools`, `venv`, `models`. Скрытые/системные каталоги не используются.
- Встроенный сборщик может по CSV создать подпапки целей и скопировать в них найденные исходные фотографии. Если в основном интерфейсе уже указана папка фотографий, сборщик использует её автоматически и спрашивает исходную папку только когда поле пустое. Во время индексации и копирования показывается прогресс; кнопка `Отмена` активна и прерывает сборку, включая текущее копирование большого файла.
- Выбранные папки, профили, критерии качества и параметры производительности автоматически сохраняются между запусками в пользовательском профиле Windows. Запись выполняется атомарно; повреждённый или несовместимый файл настроек игнорируется.
- Кнопка `Рекомендуемые значения` возвращает безопасные исходные настройки без изменения фотографий и результатов предыдущих запусков.

## Имена эталонов

Папка эталонов **всегда сканируется рекурсивно**. Название подкаталога не входит в ID ребёнка. Поэтому можно хранить, например:

```text
Эталоны/
├─ портрет/
│  ├─ Котов Никита.jpg
│  ├─ Балаева Виктория.jpg
│  └─ Синичкина.jpg
└─ стоя/
   ├─ Котов Никита.jpg
   ├─ Балаева Виктория.jpg
   └─ Синичкина.jpg
```

Получатся три ребёнка с двумя эталонами каждый: `Котов Никита`, `Балаева Виктория`, `Синичкина`. Можно добавлять третью, четвёртую и последующие подпапки/эталоны с тем же ID — жёсткого лимита количества эталонов нет.

Поддерживается и прежняя схема с номером исходного кадра в начале имени:

```text
712 Котов Никита.jpg
709 Котов Никита.jpg
```

Ведущий числовой блок удаляется, поэтому оба файла относятся к `Котов Никита`.

Также допускаются отдельные ведущие индексы из **одной заглавной латинской буквы `A–Z`**:

```text
A Котов Никита.jpg
B Котов Никита.jpg
A Smith John.jpg
B Smith John.jpg
```

В этих примерах `A`/`B` считаются служебными индексами и удаляются. При этом латиница в самом идентификаторе полностью сохраняется: `Smith John.jpg`, `McDonald Anna.jpg`, `LEE John.jpg` остаются без изменений. Строчные буквы и многобуквенные латинские слова автоматически не удаляются.

Имя может состоять из фамилии и имени, только фамилии или другой устойчивой текстовой части — на кириллице, латинице или в смешанном написании. Сначала программа объединяет все точные нормализованные имена, независимо от количества файлов. Если несколько эталонов названы немного по-разному, допускается однозначная общая часть, например:

```text
Котов.jpg                 + Котов Никита.jpg
Котов Никита портрет.jpg  + Котов Никита стоя.jpg + Котов Никита улица.jpg
```

Во втором примере все три файла получат ID `Котов Никита`. В первом — `Котов`.

Чтобы не объединить разных детей случайно, короткое совпадение из одного слова разрешается только тогда, когда одно из имён целиком состоит из этого слова. Если одна общая часть подходит сразу к нескольким файлам (например, `Котов.jpg`, `Котов Никита.jpg`, `Котов Сергей.jpg`), программа **не угадывает**, а останавливается с понятным сообщением о неоднозначных именах.

Для внутренней группировки нормализуются регистр, лишние пробелы и `е/ё`; латинские символы не удаляются. Жёсткого ограничения количества эталонов на один ID нет. Практически можно использовать столько заведомо правильно отобранных фотографий ребёнка, сколько требуется.

### Как используются несколько эталонов

Embeddings **не усредняются**. Каждый эталон хранится отдельно. Для найденного лица вычисляется distance до каждого эталона каждого ребёнка, а итоговая distance ребёнка равна **лучшему (минимальному) значению среди всех его эталонов**. Поэтому дополнительный удачный эталон может улучшить распознавание другого ракурса, выражения лица или более старой/новой фотографии.

Второй кандидат при проверке неоднозначности — обязательно **другой ребёнок**, а не ещё один эталон того же ребёнка. Поэтому несколько эталонов одного ID не конкурируют друг с другом при расчёте «отрыва от второго ребёнка».

Если у ребёнка несколько эталонов, программа проверяет их взаимную согласованность. Для всех пар вычисляется cosine distance и в журнале контролируется худшая (максимальная) взаимная distance. Если она превышает порог предупреждения, программа указывает наиболее слабо совпадающую пару файлов, но не удаляет эталоны автоматически. Это помогает заметить случайно неверно подписанный файл.

Чем больше эталонов, тем больше сравнений выполняется на этапе matching, но эта операция очень лёгкая по сравнению с детекцией и анализом лиц. Для обычных наборов из нескольких эталонов на ребёнка влияние на скорость практически несущественно.

## Поиск маленьких лиц

В GUI есть три режима:

- `Быстрый` — один проход по полному кадру.
- `Улучшенный` — полный кадр + перекрывающиеся тайлы на больших изображениях. Рекомендуемый режим.
- `Максимальный` — более мелкие тайлы и больше проходов. Лучше для очень маленьких лиц, но медленнее.

SCRFD сохраняет штатный вход `640x640` на каждом проходе. Для большого группового фото тайлы позволяют не уменьшать весь кадр до 640 пикселей целиком.

После полного кадра и тайлов bbox объединяются NMS. Дубликаты одного лица удаляются до matching.

Параметр `Порог детектора` по умолчанию `0.18`. Это чувствительность первоначального поиска SCRFD, а не критерий качества кадра. Низкий `det_score` сам по себе не выбрасывает уже найденного ребёнка из result.csv.

## Фильтр качества

Пресет `Мягкий / Нормальный / Строгий` задаёт числовые пороги. Отдельные галочки задают, какие причины действительно должны отбраковывать фото:

- закрытые/сильно прищуренные глаза;
- нерезкое лицо;
- сильный yaw/pitch/roll;
- слишком маленькое лицо;
- плохая экспозиция;
- частично обрезанная или композиционно слишком близкая к реальной границе кадра голова.

Для групповой фотографии качество считается отдельно для каждого ребёнка. Если один ребёнок моргнул, он может попасть в `rejected.csv`, а остальные дети с того же кадра — в основной CSV.

Проверка `Отбраковывать обрезанную/слишком близкую к краю голову` состоит из двух частей. Сначала проверяется физическая обрезка головы по bbox и необходимому запасу для макушки/боков/подбородка. Затем применяется адаптивная композиционная зона у края кадра: чем меньшую долю площади фотографии занимает лицо, тем больший процент ширины/высоты кадра требуется оставить до ближайшей границы. Это помогает исключать маленькие лица, случайно попавшие на край фотографии, но не делает такой же большой отступ обязательным для крупного тесного портрета. Для нормального пресета адаптивный отступ меняется примерно от `0.8%` для очень крупного лица до `5%` для очень маленького; для мягкого — `0.6–3.5%`, для строгого — `1.2–6.5%`.

Проверка глаз основана на 106 landmarks InsightFace и является эвристикой. Для спорных кадров полезно просматривать `*_rejected.csv`.

## CSV

Основной файл:

```text
Идентификатор цели;номер фото с этой целью;Исходный файл
Котов Никита;IMG_0123;группа_01\IMG_0123.jpg
Балаева Виктория;IMG_0123;группа_01\IMG_0123.jpg
```

`номер фото` — имя исходного файла без расширения. `Исходный файл` — относительный путь от выбранной папки фотографий; он позволяет однозначно находить одинаково названные файлы из разных подпапок.


### Последовательные серии и лучший кадр

Опция `Определять серии фотографий и выбирать лучший кадр для каждой цели` создаёт дополнительный `*_best.csv`. Полный основной CSV при этом **не сокращается** и по-прежнему содержит все найденные хорошие кадры.

Серии определяются **отдельно для каждой уже распознанной цели**. Это важное отличие от общего портретного селектора: ChildFaceFinder не пытается заново кластеризовать людей внутри серии, а использует подтверждённую идентичность по референсам. Алгоритм последовательности основан на портретном режиме `photo_select_ai`:

- кадры должны находиться в одной исходной папке;
- для обычной последовательности камеры используется последний числовой номер имени файла и его префикс (`IMG_4048`, `IMG_4049`, ...);
- допустимый разрыв между соседними найденными кадрами — до 5 номеров файла;
- при надёжном EXIF-времени серия разрывается при паузе больше 12 секунд;
- если EXIF отсутствует, камера с последовательной нумерацией считается более надёжным источником порядка, чем файловый mtime;
- если между двумя кадрами цели есть минимум два кадра другой уже распознанной цели, это считается подтверждённой границей A/B/A и серии не склеиваются; один случайный чужой кадр границу не создаёт;
- одиночный найденный кадр остаётся отдельной серией и не теряется.

Внутри серии сначала предпочитаются кадры с надёжно открытыми глазами. Затем рейтинг учитывает резкость лица (нормализованную внутри конкретной серии), уверенность совпадения с референсом, ракурс головы и `det_score`. Поэтому крупное лицо не получает автоматическое преимущество только из-за более высокого абсолютного Laplacian.

Первые три столбца `*_best.csv` совпадают с основным CSV, поэтому этот файл можно напрямую передать встроенному сборщику и получить по одному лучшему кадру из каждой серии каждой цели. Дополнительные столбцы содержат номер серии, количество кадров, итоговый score и диагностические метрики выбора.

### Сборщик файлов по CSV

Кнопка `Собрать файлы по CSV…` создаёт в выбранном каталоге подпапки по именам целей и копирует туда найденные фотографии. Оригиналы не удаляются и не перезаписываются.

Если поле `Папка фотографий` в основном окне заполнено, сборщик автоматически использует именно эту папку и не задаёт повторный вопрос. Диалог выбора исходной папки появляется только если поле пустое. Если указанный в интерфейсе путь больше не существует, сборщик сообщает об ошибке и просит исправить или очистить поле.

Для нового CSV используется столбец `Исходный файл`. Старые двухколоночные CSV тоже поддерживаются: сборщик индексирует выбранную папку по stem имени файла; неоднозначные совпадения не угадываются и фиксируются в `collector_report.csv`. Во время индексации отображается отдельная стадия прогресса, а при копировании — `обработано / всего` и текущая цель/файл. Во время сборки кнопка `Отмена` активна: она останавливает индексацию или копирование, уже полностью скопированные файлы сохраняются, а частично записанный текущий файл удаляется. `collector_report.csv` создаётся и при отмене.

Дополнительно:

- `*_rejected.csv` — ребёнок распознан, но фото исключено включённым фильтром качества;
- `*_review.csv` — совпадение близко к порогу или слишком близка вторая цель;
- `*_best.csv` — создаётся только при включённой опции серий и содержит по одному лучшему кадру каждой последовательной серии каждой цели.

## Форматы изображений

Обычные форматы читаются через Pillow/OpenCV: JPEG, PNG, TIFF, BMP, WebP и другие поддерживаемые форматы.

HEIC/HEIF/AVIF читаются через `pillow-heif`/Pillow.

RAW читается через `rawpy` / LibRaw: CR2, CR3, NEF, ARW, DNG, RAF, RW2, ORF и многие другие. Поддержка конкретного нового/редкого RAW зависит от LibRaw.

### TEMP

Для RAW сначала извлекается встроенный JPEG-preview без полной проявки сенсорных данных. Если preview отсутствует или слишком мал, используется быстрый `half_size=True` fallback LibRaw. Рабочая копия ограничивается 4096 px по длинной стороне. HEIF и редкие неизвестные форматы при необходимости нормализуются через системный `%TEMP%`.

- рядом со скриптом временные изображения не создаются;
- временный JPEG удаляется сразу после чтения обратно в память;
- общий каталог создаётся через `tempfile.TemporaryDirectory` и удаляется при успехе, ошибке или штатной отмене;
- временные ZIP установщика и модели также находятся в системном TEMP и удаляются.

## GPU и параллельная обработка

Основная конфигурация — NVIDIA GPU через `onnxruntime-gpu 1.26.0`/CUDA Execution Provider.

Конвейер разделён:

- несколько CPU-потоков декодируют обычные изображения и RAW;
- отдельные inference-потоки используют общие ONNX/InsightFace модели на GPU;
- очередь ограничена; RAW не проявляется без необходимости в полном разрешении, поэтому расход CPU/RAM существенно ниже.
- `.xmp` и другие служебные файлы пропускаются и не передаются декодеру.

Для RTX 5090 рекомендуется начать с `2` параллельных GPU-сеансов. Если GPU заметно недогружен, можно попробовать `3–4`.

## Установка

Текущий установщик рассчитан на 64-битную Windows с NVIDIA GPU. Для установки нужен доступ к GitHub, PyPI и `files.pythonhosted.org`, а также запас свободного места для крупных CUDA/cuDNN wheels. Рекомендуется актуальный драйвер NVIDIA и Microsoft Visual C++ 2015–2022 Redistributable x64. Для CUDA 12.x установщик заранее отклоняет драйвер Windows старее `528.33`; отдельный CUDA Toolkit устанавливать не требуется.

Системный Python не используется и не изменяется. Установщик использует системное хранилище сертификатов Windows, повторяет кратковременно неудачные сетевые загрузки и хранит тяжёлый `uv`-кэш только во временном каталоге `%TEMP%`.

Перед установкой выполняются проверки архитектуры, обязательных файлов, возможности записи, свободного места, NVIDIA GPU/драйвера и VC++ runtime. При повторной установке существующий `venv` временно переносится в резервную папку, пока создаётся и проверяется новый; если установка обрывается, неполное окружение удаляется, а прежнее автоматически восстанавливается. Модель `antelopev2` также заменяется транзакционно: старая рабочая копия не удаляется до полной подготовки новой.

1. Запустите `install.bat`.
2. В видимую папку `tools` будет установлен зафиксированный `uv 0.12.5`.
3. `uv` установит собственный CPython `3.11.16` в `tools/python`.
4. Будет создана видимая папка `venv`.
5. Установятся зафиксированные зависимости и `insightface==1.0.1`.
6. Проверятся Tkinter и CUDA Execution Provider.
7. `antelopev2` будет установлен в `models/insightface/models/antelopev2`.
8. Выполнится GPU/model smoke-test.

После успешной установки запускайте `run.bat`. Для диагностики с консолью можно запустить `setup\run_console.bat`. При обычном запуске `run.bat` теперь показывает короткие этапы — проверка приватного Python, проверка окружения и запуск интерфейса — вместо пустого чёрного окна.

### Перенос и переименование папки программы

Папку Child Face Finder можно переименовать или переместить целиком, в том числе на другой локальный диск. При следующем запуске `run.bat` проверяет `venv\pyvenv.cfg` и атомарно обновляет сохранённую там привязку к текущему `tools\python`. Та же проверка выполняется при запуске `setup\run_console.bat`. Переустанавливать программу только из-за изменения пути не требуется.

Пути к приложению, моделям и встроенному Python вычисляются относительно текущего местоположения файлов программы. Маркер незавершённой транзакции установщика также хранит относительное имя резервного окружения, поэтому восстановление остаётся работоспособным после переноса всей папки.

Выбранные пользователем папки эталонов, фотографий и CSV намеренно остаются абсолютными внешними путями. Если вместе с программой были перемещены и эти данные, выберите их новое расположение в интерфейсе.

При копировании уже установленной папки на другой компьютер автоматическое исправление пути также выполняется, но на новом компьютере всё равно должны присутствовать совместимые драйвер NVIDIA и Microsoft Visual C++ Runtime. Для гарантированной проверки зависимостей рекомендуется один раз запустить `install.bat`.

## Лицензия моделей InsightFace

У кода InsightFace и у предоставляемых проектом предобученных моделей разные условия. Перед использованием `antelopev2` в коммерческой работе необходимо проверить актуальные условия лицензирования InsightFace/model zoo.


### GPU runtime

Установщик фиксирует `onnxruntime-gpu 1.26.0`, `nvidia-cudnn-cu12 9.7.1.26` и весь используемый набор CUDA 12.8 wheel-компонентов (`runtime`, `nvrtc`, `cuBLAS`, `cuFFT`, `cuRAND`, `nvJitLink`). Это сделано намеренно: `onnxruntime-gpu[cuda]` допускает совместимые диапазоны версий, поэтому без дополнительных pin повторная установка позднее могла бы получить уже другой набор NVIDIA DLL. Дополнительно `uv` использует фиксированную дату `exclude-newer`, поэтому и транзитивные зависимости не начнут незаметно меняться при будущей переустановке этой версии.

## Очистка временных файлов

Рабочие временные файлы создаются только в системном TEMP. В нормальном режиме отдельные временные файлы удаляются сразу после использования, а рабочий TEMP-каталог удаляется при завершении обработки, ошибке или штатной отмене.

Для защиты от остатков после аварийного завершения рабочие каталоги имеют имя `ChildFaceFinder_run_<PID>_*`. При следующем запуске GUI и повторно перед обработкой программа проверяет TEMP и удаляет каталоги предыдущих экземпляров, процесс которых уже не существует. Активный каталог другого одновременно работающего экземпляра не удаляется. Каталоги старых версий без PID удаляются только после защитного периода, чтобы не затронуть параллельно работающую старую версию.


## Диагностика установки

Автономная установка сохраняет полный журнал в `childfacefinder_install.log` в корне программы. `install.bat` сообщает об успешной установке только после отдельной проверки того же `venv\Scripts\python.exe`, который затем использует `run.bat`. Если первый запуск сообщает, что окружение отсутствует, установка не считается завершённой; пришлите этот лог.
